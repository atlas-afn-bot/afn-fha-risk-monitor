Promotion flow

feature/xxx  ──PR──▶  dev  ──Standing PR──▶  main  ──deploy──▶  prod
  1. Feature work lands on dev via a normal PR (CI + 1 review, deploys automatically to dev SWA).
  2. Soak on dev. Michael's discretion — no timer.
  3. A standing dev → main PR is auto-opened by .github/workflows/promotion-pr.yml, auto-updates on every dev merge, and auto-reopens after each promotion. Bookmark it: github.com/afncorp/afn-fha-risk-monitor/pulls (dev → main).

Approving/merging the standing PR = approving the prod deploy. There's no separate deploy-approval step (GitHub's environment-reviewer feature isn't available on the Team plan for private repos; we get functionally-equivalent gating via branch protection + admin-bypass-disabled on main).

Hotfix path

Emergency changes: branch from main, PR into main directly (bypasses dev). Same protections apply — still needs one approver to merge. After merge, follow up with a main → dev backport PR so dev stays consistent.

Rollback

Every prod deploy is a single squash commit on main. Rollback = git revert <sha> on main → opens a PR → same approval flow → merge → prod redeploys the prior state. Roughly 5–10 min end-to-end.
